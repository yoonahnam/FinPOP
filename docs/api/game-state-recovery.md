# 게임 상태 복원

## 동작

- 로그인 담당 코드가 사용자 프로필을 확인한 뒤 기존처럼 bindUser → start를 호출합니다. 자동 로그인·로그아웃 정책과 팀원 화면 디자인은 변경하지 않습니다.
- 같은 계정으로 재진입하면 메모리 상태를 그대로 믿지 않고 서버 게임 조회를 먼저 실행합니다.
- 프로세스 종료 후에는 계정별로 저장한 게임 ID로 조회합니다. 저장된 ID가 없을 때만 생성 요청을 보내며, ACTIVE_GAME_EXISTS 응답이면 기존 대결을 조회합니다.
- 현재 차례·퀴즈 문항·보기·마감 시각·구매 대기·잔액·소유권·PAUSED 상태는 서버 응답에서 복원합니다. 일시정지한 대결을 자동으로 재개하지 않습니다.
- 답변·구매·포기 등 응답이 불확실한 변경 요청은 원래 요청 키와 본문을 유지해 재전송합니다. 캐시된 최초 응답이 오래됐을 수 있으므로 최신 GET 조회가 완료되기 전에는 AI나 팝업에 반영하지 않습니다.
- 변경 요청은 성공했지만 이후 GET만 실패한 경우, 다음 시도에는 조회만 수행합니다.
- 백그라운드에서는 후속 AI 요청과 클라이언트 시간 초과 요청을 중단하고, 복귀하면 서버 조회 후 진행합니다. 이미 보낸 서버 요청은 완료될 수 있습니다. 백그라운드 이동 자체가 서버 일시정지는 아니므로 ACTIVE 퀴즈의 마감 시각은 계속 흐릅니다.
- AI 결과를 확인한 기록을 저장한 뒤 구매·차례 종료를 이어갑니다. 이미 확인한 같은 결과는 재표시하지 않고, 미확인 결과는 확인을 기다립니다.
- 복원 중 과거 이동 경로·구매 도장 애니메이션은 재생하지 않습니다. 새 구매 이벤트도 ID를 기록해 같은 이벤트의 중복 재생을 막습니다.
- 사용자가 구매·패스를 확정한 뒤 종료 요청 직전에 앱이 종료돼도 같은 차례라면 마무리를 이어갑니다.
- 프로세스 복원으로 화면 진입 플래그만 남아 있어도 사용자 세션을 연결하기 전에는 빈 보드에 진입하지 않습니다.

## 저장하는 정보

앱 전용 SharedPreferences에 사용자 ID별 게임 ID, 미확정 명령의 요청 키·본문, AI 결과 확인 ID, 구매 애니메이션 이벤트 ID, 마무리할 차례 ID만 보관합니다. 문항·정답·전체 게임 스냅샷·인증 토큰·비밀번호는 저장하지 않습니다. 이 확인 기록은 현재 기기 기준이며 다른 기기와 동기화하지 않습니다.

손상된 기록이나 저장 실패는 새 요청 키로 우회하지 않고 오류로 안내합니다. 저장에 실패하면 변경 요청을 보내지 않습니다. 앱 데이터 삭제·재설치로 기록이 삭제되면 서버의 활성 대결 조회 경로로 복원하지만, 기기에만 있던 팝업 확인 기록은 복구할 수 없습니다.

## 확인 방법

1. 일반 app에서 로그인하고 퀴즈가 열린 상태로 앱을 종료·재실행합니다. 다시 로그인해 같은 문제·차례와 서버 기준 남은 시간이 보이는지 확인합니다.
2. PAUSED 대결을 재실행하면 일시정지 안내를 유지하는지 확인합니다.
3. 구매 대기 상태에서 재실행해 선택을 이어가고, 구매 직후 종료했다면 차례 마무리가 한 번만 처리되는지 확인합니다.
4. AI 결과를 확인하기 전·후 각각 재실행해 미확인 결과만 다시 표시하는지 확인합니다.
5. 백그라운드 복귀와 상태 새로고침으로 이전 이동·구매 애니메이션이 재생되지 않는지 확인합니다.
6. 계정 변경 시 이전 계정의 게임·미확정 요청이 새 계정에 표시되지 않는지 확인합니다.

이번 변경은 Android 코드만 사용합니다. 기존 일시정지·재개·포기 SQL과 Edge Function이 배포된 서버에서 추가 DB 변경이나 함수 재배포 없이 확인할 수 있습니다. 로그인 이후 실제 서버 통합 검증은 별도 수행합니다.

로컬 검증: JDK 17에서 gradlew.bat :app:assembleDebug :app:testDebugUnitTest --offline.
